# Contributing to OpenMarket AI Agent

Thank you for your interest in contributing to OpenMarket AI Agent!

We are building a free, open-source, community-driven financial intelligence research platform for people around the world.

We welcome developers, AI engineers, quantitative researchers, financial analysts, data scientists, designers, technical writers, and open-source enthusiasts.

## 1. Our Mission

Our mission is to make advanced financial market research accessible to everyone through transparent, responsible, and open-source artificial intelligence.

We value:

- Free and open access
- Transparency and reproducibility
- Scientific integrity
- Responsible financial research
- Security and privacy
- Respectful international collaboration
- Clear and maintainable code

## 2. Ways to Contribute

You can contribute by:

- Improving Python code and architecture
- Developing AI research agents
- Researching technical indicators
- Improving fundamental analysis
- Building reproducible backtesting tools
- Reviewing market data quality
- Writing tests and documentation
- Improving accessibility and translations
- Reporting bugs
- Proposing new features
- Reviewing pull requests

Contributions are welcome regardless of experience level.

## 3. Getting Started

1. Read the README.md and ROADMAP.md files.
2. Review existing GitHub Issues and Pull Requests.
3. Open an Issue to discuss significant new features before implementation.
4. Fork the repository to your GitHub account.
5. Create a descriptive branch for your work.
6. Make focused changes and add relevant tests.
7. Open a Pull Request explaining your changes.

As the technical codebase develops, setup and testing instructions will be published.

## 4. Development Standards

We aim to use Python as the primary development language.

Contributors should:

- Write clear and readable code.
- Follow PEP 8 conventions where applicable.
- Use descriptive function and variable names.
- Document important assumptions.
- Add type hints where practical.
- Include tests for new functionality.
- Avoid unnecessary dependencies.
- Keep modules independent and maintainable.

Automated development tools and code quality checks will be introduced as the project matures.

## 5. Financial Research Standards

Financial research contributions must prioritize accuracy and reproducibility.

When proposing a strategy or analytical method:

- Explain the research hypothesis.
- Identify the market and timeframe.
- Document data sources and licensing conditions.
- Avoid look-ahead bias and data leakage.
- Include realistic trading costs when relevant.
- Use out-of-sample evaluation where possible.
- Report limitations and uncertainty.
- Never promise guaranteed returns.
- Distinguish hypothetical, backtested, paper-trading, and live results.

Unverified profitability claims are not acceptable.

## 6. Responsible AI Development

AI-related contributions should:

- Document the models and data used.
- Explain important model limitations.
- Avoid presenting generated predictions as facts.
- Support transparent and explainable outputs.
- Include evaluation methods where practical.
- Respect user privacy and data licensing.
- Avoid fabricated market data, citations, or performance results.

## 7. Security and Privacy

Never commit:

- API keys or access tokens
- Passwords or private credentials
- Brokerage account credentials
- Personal financial information
- Private user data
- Proprietary datasets without permission

Use environment variables and local configuration files for secrets.

Do not disclose security vulnerabilities publicly before responsible review. Until a formal security policy is published, contact the repository maintainer privately through an appropriate GitHub channel when available.

## 8. Pull Request Guidelines

Each Pull Request should include:

- A clear title
- A summary of the changes
- The reason for the changes
- Related GitHub Issue references, if applicable
- Testing instructions and results
- Any relevant risks or limitations

Keep Pull Requests focused and reasonably sized.

Project maintainers may request changes before merging.

## 9. Community Conduct

All contributors must treat one another respectfully.

Harassment, discrimination, personal attacks, spam, and abusive behavior are not acceptable.

A formal CODE_OF_CONDUCT.md will provide additional community standards.
